# 下一阶段插件工作计划

更新：2026-11-19。

本计划承接 [阶段总结](../research/phase-summary-2026-11-19.md)。
下一阶段的核心仍然是 `astrbot_plugin_social_agent`，不是单独做展示材料。

## 目标

把已经通过真实发帖验收的最小插件，扩展为一组有明确能力边界、统一结果、
可追踪任务状态和可重复测试的微博工具；工具链稳定后，再做角色行为模拟。

## 阶段 2A：插件工具链

| 顺序 | 工作 | 产物 | 验收条件 |
| --- | --- | --- | --- |
| 1 | 能力清单与统一结果 | `weibo_capabilities`、错误码和验证级别 | 能明确区分已实现、部分支持和未实现 |
| 2 | 正式读取工具 | 动态、用户微博、详情、评论列表工具 | 真实读取结果可保存并按统一结构返回 |
| 3 | 评论创建 | 草稿、确认、单次提交、结果读回 | 指定测试微博下成功评论并核验正文 |
| 4 | 评论回复 | `cid` 与微博 ID 定位、确认和核验 | 能区分评论创建和指定评论回复 |
| 5 | 点赞操作 | 点赞/取消点赞适配器或明确缺口 | 先完成只读和按钮状态验证，再决定是否提交 |
| 6 | 任务治理 | 取消、过期、未知补核验、同文去重 | 异常场景不重复写入、不误报成功 |
| 7 | 测试与部署 | 回归测试、安装脚本、版本说明 | 本机 AstrBot 与隔离测试环境结果一致 |

## 阶段 2B：角色行为模拟

角色模拟必须调用阶段 2A 的正式插件工具，不能直接在角色层拼接浏览器操作。

### 最小角色模型

- 角色目标：例如项目账号运营助手。
- 语气与风格：正式程度、句式、常用表达和禁用表达。
- 行动范围：允许发帖、回复、点赞建议；默认不自动提交。
- 记忆：账号简介、近期已发内容、已处理评论和任务结果。
- 安全边界：不处理敏感主题，不绕过确认，不执行未注册工具。

### 实验步骤

1. 固定模型、主题、微博和评论输入。
2. 运行“无角色配置”和“有角色配置”两组对照。
3. 记录发帖、回复、点赞建议和不行动的选择。
4. 由组员按相关性、自然度、风格一致性、行动合理性评分。
5. 统计越权调用、重复操作、无依据行动和拒绝理由。
6. 先离线重放，再做人工确认的真实平台小规模执行。

## 不纳入近期主线的内容

- 一次性实现官方 CLI 的全部 75 项接口。
- 在没有稳定适配器时伪造点赞、评论或转发工具。
- 多账号和大规模批量操作。
- 自动营销、刷互动和不受控的自主发布。
- 为了汇报提前制作与代码事实脱节的 PPT。

## 每项工具的完成定义

一个工具只有同时满足以下条件，才从 planned 变为 verified：

1. 有明确输入和输出契约。
2. 有权限、归属和参数校验。
3. 有真实网页或官方后端的固定执行路径。
4. 有成功、失败、超时或未知状态处理。
5. 有平台结果读回或页面证据。
6. 有隔离测试和至少一次受控真实验收。
