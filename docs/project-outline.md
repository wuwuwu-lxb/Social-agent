# 项目大纲 v0.1

2026-11-12 补充：当前以实际落地和学习为先。本文保留大框架，八周安排与汇报结构仅供后续参考。接入步骤、相关案例及文献统一放在 `research/`；账号主题不再预设为项目进展分享。

## 1. 暂定题目与场景

题目：基于 AstrBot 的社交媒体智能体设计与实现。

初始场景：小组运营一个项目进展分享账号。智能体根据本周进展生成帖子，理解测试帖下的评论，提出回复和点赞建议，经过确认后执行。

项目重点是“理解内容、选择行动、可控执行与效果评估”。底层消息接入及模型调用尽量复用 AstrBot，小组重点完成任务流程、平台适配、记忆和评测。

## 2. 拟研究的问题

1. 相比直接提示模型生成文本，加入账号风格和历史信息能否提升内容一致性？
2. 如何让模型给出的发帖、评论、点赞建议稳定转换为可检查的操作？
3. 平台请求超时、权限不足或重复触发时，如何避免误报成功和重复发布？

以上为拟验证问题，不作为已实现创新点或已取得结论。

## 3. 架构草案

```text
用户输入 / 后期定时触发
            |
       AstrBot 插件
            |
   内容理解与行动建议 <---- 账号风格 / 历史记录
            |
    参数校验与人工确认
            |
       平台适配层
       /         \
 本地模拟平台    微博等真实平台
       \         /
      执行结果与状态核验
            |
       SQLite / 操作日志
```

建议任务状态：草稿、待确认、执行中、成功、失败、结果未知、已取消。

请求超时不等同于失败。若可能已发布但未收到响应，先查询或人工核对，再决定重试。权限不足、登录失效和不支持的功能应给出明确状态。

## 4. 第一版边界

- 一个目标平台、一个测试账号，以文本为主。
- 仅对指定测试内容或允许互动的对象执行操作。
- 发帖、评论和点赞先采用确认后执行，待稳定后再讨论自动化范围。
- 每次操作记录任务编号、目标、生成内容、确认状态、时间和平台结果。
- 凭据、登录态和未脱敏数据不进入 Git；公开演示材料使用脱敏截图。
- 暂不开展批量营销、刷互动、推荐算法研究和大规模数据采集。

## 5. 八周暂定计划

实际周数与日期待课程安排确认；W01 表示项目第一周，不代表日历周。

| 周次 | 本周交付 | 汇报展示与验收 |
| --- | --- | --- |
| W01 | 明确需求；搭建 AstrBot；验证平台账号、权限和费用 | 选型表、环境截图、每项平台能力的验证记录 |
| W02 | 最小插件与模拟平台 | 输入主题，输出结构化草稿，完整记录一次模拟任务 |
| W03 | 真实平台发帖闭环 | 确认后发布；保存平台返回标识并查询结果；若受阻，展示阻碍与备选决策 |
| W04 | 评论与点赞 | 在测试内容上分别验证评论、点赞和重复操作处理 |
| W05 | 账号风格与历史记忆 | 对比有无风格、历史信息的生成效果 |
| W06 | 定时任务与异常处理 | 验证过期授权、请求超时、任务取消和重复触发 |
| W07 | 系统评测与缺陷修复 | 给出数据集、评价方法、结果及失败案例 |
| W08 | 完整演示与结题材料 | 重现演示流程，整理安装说明、报告和最终 PPT |

## 6. 建议分工

暂按四个职责划分，可按人数合并；每项任务安排一名负责人和一名复核人。

| 职责 | 主要工作 | 产物 |
| --- | --- | --- |
| 集成与项目管理 | AstrBot 插件、任务流程、联调、进度管理 | 可运行入口、集成演示、任务清单 |
| 平台接入 | 登录授权、平台适配、结果查询、异常处理 | 能力矩阵、适配实现、验证记录 |
| 智能体策略 | 提示词、账号风格、历史记忆、行动生成 | 策略配置、样例、对比实验 |
| 评测与材料 | 用例、缺陷记录、操作统计、周报汇总 | 测试结果、周报、PPT |

每个人都参与开发与讲解，汇报材料负责人不等于专职制作 PPT。

## 7. 评估方法

- 功能完成率：固定任务集中，得到可核验结果的任务数 / 总任务数。真实平台与模拟平台分别统计。
- 执行稳定性：按发帖、评论、点赞分别记录成功、失败和结果未知的数量。
- 内容质量：固定一组主题与评论，由组员按相关性、自然度、账号风格一致性评分。
- 对照实验：比较“基础提示词”和“加入账号风格与历史信息”，保持模型与输入一致。
- 时间与成本：记录单次任务耗时、模型用量和可获取的平台费用。
- 边界行为：检查未经确认、重复触发、过期授权和超时场景。

不以点赞数、粉丝增长量作为主要验收指标。量化通过门槛在基线验证后由小组确定。
