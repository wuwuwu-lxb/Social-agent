# 阶段总结：Social Agent 插件最小闭环验收

日期：2026-11-19。

## 1. 阶段结论

本阶段完成的核心成果不是“做了一个 PPT”，而是完成了一个可运行的
AstrBot 插件，并通过真实微信入口和真实微博账号的发帖验收：

```text
微信私聊
  -> AstrBot 接收消息
  -> Social Agent 插件生成并保存微博草稿
  -> 浏览器适配器预演微博发帖页面
  -> 用户确认任务
  -> 专用 Edge 会话执行真实发布
  -> 读取微博详情核对正文
  -> 微信返回发布结果
```

用户已确认发帖功能正常运行，第一阶段验收通过。这里的“通过”指真实
账号完成了公开文本微博发布，不把模拟夹具、按钮点击或模型口头回复当作
真实成功证据。

当前首版边界：

- 只支持公开纯文本微博，长度为 1-140 个字符。
- 发布前必须展示最终文案，并由白名单本人发送确认命令。
- 发布时选择网页“内容由AI生成”。
- 只允许一个配置好的微博账号和一个受控浏览器 profile。
- 图片、评论、回复、点赞、转发、定时任务和多账号尚未纳入首版。

## 3. 版本与交付物

### 3.1 当前真正运行的插件

目录：`astrbot_plugin_social_agent/`

- `main.py`：AstrBot 入口、模型工具和聊天命令。
- `social_agent/service.py`：草稿、任务、确认、幂等和结果状态。
- `node/executor.mjs`：固定 Node 执行入口、浏览器 profile、网络安全闸门。
- `node/publish.mjs`：微博发帖页面操作、提交和详情读回核验。
- `metadata.yaml`、`_conf_schema.json`：插件元数据和配置。

### 3.3 验证材料

- AstrBot PluginManager 能加载插件并注册 `weibo_statuses_update`。
- 微信私聊能够触发草稿和确认命令。
- Python 测试覆盖任务原子认领、并发确认、重启后重复确认、权限和未知状态。
- Node 夹具测试覆盖成功响应、正文读回、正文不符、平台拒绝和无请求点击。
- 真实环境已完成一次公开文本微博发布并核对结果。
- 真实账号、浏览器登录态、任务数据库和白名单没有提交到 GitHub。

真实验收采用用户实际微信操作后的确认作为证据；项目没有保存微博账号、
帖子链接或个人标识，因此后续汇报应引用“用户实测验收”，不得补造截图、
微博 URL、发布时间或精确运行次数。

## 4. 这阶段解决的工程问题

1. **官方 CLI 与实际落地的关系**：CLI 目录用于接口命名和参数参考，
   不把 75 项目录误报为已实现功能。
2. **动态网页定位问题**：使用 webmcp 适配器和固定 Playwright 操作，
   不在每次请求时生成任意浏览器脚本。
3. **确认与权限问题**：模型只能准备草稿，真实提交必须由白名单本人确认。
4. **重复发布问题**：SQLite 原子认领和发布记录保证同一任务只执行一次。
5. **超时和误报问题**：提交失败、提交后未知和核验失败分开记录，
   不把“模型说发布了”当作平台成功。
6. **安全放行问题**：只放行正文精确匹配的一条微博更新请求，其余微博写请求
   拦截；对 JSON、URL 编码表单和 multipart 原始正文做匹配。

## 5. 下一阶段目标：继续做插件

下一阶段不再重复证明“微信能发一条微博”，而是把首版插件扩展成可验证的
社交媒体工具链，再在工具链之上实现角色行为模拟。

### 5.1 工具链完善顺序

1. **能力查询和统一错误**：增加插件能力清单，明确每个工具的参数、后端、
   验证级别和当前限制。
2. **微博读取工具**：将首页动态、用户微博、单条详情、评论列表迁移为正式
   插件工具，统一 ID、分页和结果结构。
3. **评论工具**：先实现评论创建，再实现指定评论回复；每项都需要确认、
   单次提交和平台结果核验。
4. **点赞工具**：先验证网页是否有稳定的点赞/取消点赞操作，再决定是否纳入
   首版工具契约；没有稳定适配器时不伪装成已支持。
5. **任务治理**：补充取消、过期确认、未知结果补核验、同文去重和审计日志。
6. **内容扩展**：在文本闭环稳定后，再评估图片、转发、定时任务和多账号。

### 5.2 角色智能体行为模拟

角色模拟建立在已验收插件上，不直接绕过插件调用微博：

```text
角色配置 + 历史记忆 + 当前微博内容
  -> 模型提出行动建议
  -> 插件能力和权限校验
  -> 人工确认或受控自动策略
  -> 浏览器适配器执行
  -> 平台结果核验
  -> 记忆与行为日志
```

建议先做离线和半自动实验：

- 固定一个角色目标、表达风格、禁用主题和行动范围。
- 准备固定主题、微博和评论样例，离线重放相同输入。
- 比较基础提示词与角色配置在发帖、回复、点赞和“不行动”上的差异。
- 记录相关性、自然度、风格一致性、行动合理性和越权率。
- 只有策略稳定后，才在受控真实账号上执行少量操作。

角色智能体不是下一阶段的第一步。优先保证工具契约、权限、任务状态和
平台核验稳定，否则角色层只会把不稳定的网页操作放大。
