# 当前实施路线

更新：2026-11-19。主线是 AstrBot 插件调用微博浏览器执行器与 webmcp 适配器。
官方 CLI 用作完整接口参照；授权和命令目录探索已完成，不作为浏览器
主线的配额或开发者认证前置条件。

## 当前事实

- 本机已有 AstrBot 4.29.4；2026-11-13 用户确认微信端工具联调通过。
- webmcp 16 个工具已枚举；真实首页动态、单条详情、评论列表读取通过。
- 发帖预演和真实公开文本发布均已通过；真实发布由用户于 2026-11-19 确认验收成功。评论和点赞尚未在正式插件中实现。
- 正式 v0.1.0 已部署，真实后端日志确认加载与模型工具注册；SDK 注册表调用、草稿保存查询及浏览器预演通过，微信端验证由用户确认通过。
- 官方 CLI 的 75 项定义已导出，包含完整参数；不等于浏览器或插件实现了 75 项。

## 已验收的最小发布闭环

第一阶段已完成：微信请求 -> `weibo_statuses_update` ->
保存草稿与浏览器预演 -> 返回任务编号及最终文案 ->
本人确认 -> 真实微博发布 -> 核对结果。
具体指令和能力边界见 [插件说明](../astrbot_plugin_social_agent/README.md)。
2026-11-17 v0.2.0 已部署确认及实际发布入口，支持公开文本、页面 AI 声明选择、
单次提交和正文读回。后续修复请求正文匹配后，用户通过微信实测真实发布成功并确认验收。
详见 [发布实现记录](publishing-2026-11-17.md) 和
[阶段总结](phase-summary-2026-11-19.md)。

真实公开文本发帖已由用户确认验收通过。下一阶段转为扩展插件的正式工具链，
并以这条已验收链路作为后续功能的执行与安全基础。

自然语言入口使用插件注册的模型工具；微博执行继续用已经登录的专用
Edge。同一台电脑上的 AstrBot、Node 和浏览器执行环境需要可用。

实现分工：

| 层 | 工作 |
| --- | --- |
| AstrBot / 微信通道 | 接收消息、模型理解与工具调用、返回文本 |
| 项目插件 | 权限、参数、草稿、确认、任务与结果记录 |
| 浏览器执行器 | 固定操作、登录检查、页面执行与平台核验 |
| 契约与能力清单 | 官方名称、支持参数、后端差异与验证状态 |

完整模块设计、参数子集与状态流转见 [正式插件设计](../docs/plugin-design.md)。
不先实现完整统计、文章或多平台功能，不以做完 75 项作为首条发帖验收前提。
